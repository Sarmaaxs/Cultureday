# Culture Day Ticket Control

A mobile-friendly React/Vite app for issuing Culture Day tickets and scanning them at the door. It connects to the Supabase project and Edge Functions already prepared for this event.

## Included

- Email/password signup and sign-in through Supabase Auth.
- Generate **200 real tickets** and a separate **25-ticket test event**.
- Download all tickets in a 3-column print sheet or download one ticket at a time.
- Ticket codes are kept in this device browser storage so the same batch can be downloaded again.
- QR tokens are generated by the Edge Function; only SHA-256 hashes are stored in the database.
- Camera scanner and manual token entry.
- Only the first successful scan returns `VERIFIED`; duplicates and invalid tokens return `INVALID`.
- Backend/network failures show `OFFLINE` and never approve entry.
- Ordinary phone camera apps can read the QR token but do not redeem it.

## Run locally

1. Install Node.js 20 or newer.
2. Extract this ZIP and open a terminal in the project folder.
3. Install dependencies:

   ```bash
   npm install
   ```

4. Copy `.env.example` to `.env` (the provided values are for the already-connected project):

   ```bash
   cp .env.example .env
   ```

5. Start the app:

   ```bash
   npm run dev
   ```

6. Open the local URL shown by Vite. Camera access requires HTTPS or localhost. On Android, allow the app Camera permission when prompted.

## First use

1. Create an account using an email you control.
2. If Supabase email confirmation is enabled, confirm the email and sign in.
3. Generate the 200 real tickets. Use **Download all** for a 3-column printable sheet, or select a ticket number and choose **One ticket**.
4. Generate the 25 test tickets separately. The test event has its own event ID and cannot consume real tickets.
5. Select the correct event in the Scanner tab before scanning.

The account that creates the event is automatically added as its manager/scanner. For another scanner operator, an existing manager must add that user's Auth UUID to `public.event_staff` for the relevant event. Do not share the manager login if separate staff accounts are required.

## Deployment

Deploy the project to any static host that supports Vite (for example Vercel or Netlify). Set these build environment variables:

- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_PUBLISHABLE_KEY`

Use the values in `.env.example`. Never put a Supabase `service_role` or secret key in frontend environment variables.

## Important operating notes

- Generate the real batch only once. The creation endpoint creates a new event and tickets every time it is called; it does not reuse an existing batch.
- The app stores the returned QR tokens in this device browser storage to allow repeat downloads. Keep this device and its browser data private. If its storage is cleared or you switch devices, the raw QR tokens cannot be retrieved from the database. Do not generate a replacement batch unless you intend to invalidate/manage the previous batch separately.
- Keep the real PDF private. Anyone with a copied QR token could attempt to enter before its first redemption.
- The browser keeps a local list of event IDs on that device. If browser storage is cleared, the event still exists in Supabase but its ID must be recovered by the event manager.
- Test QR codes must be scanned with the TEST event selected.
- A failed request, missing connection, expired session, or backend outage is never a valid entry.

## Backend expected

This app expects these active Edge Functions:

- `create-event-tickets`
- `verify-ticket`

It expects the backend schema/functions already installed for `events`, `event_staff`, `tickets`, `scan_attempts`, `incidents`, `create_event_with_tickets`, and `verify_ticket`.

## Android APK build

This project includes a GitHub Actions workflow at `.github/workflows/android-apk.yml`. Push the project to a GitHub repository on the `main` branch, then open **Actions → Build Android APK**. The workflow builds a debug APK and attaches it as an artifact. This is an unsigned debug APK for installation/testing, not a Play Store release. The build must complete successfully before an APK exists.
